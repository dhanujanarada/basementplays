# TypeScript, React, and Next.js

- **Status:** implemented
- **Covers:** `src/app/`, `src/components/`, `src/lib/`, `next.config.ts`, `tsconfig.json`
- **Last checked:** 8de3320

The site uses the Next.js App Router with TypeScript strict mode. Most pages are
server components; only interactive UI is client code.

## Server components by default

A file without `"use client"` runs on the server. It can be `async`, call
Payload, and return HTML plus serialized props. `events/[slug]/page.tsx` is a
server component: it loads `EventView` and picks a design.

```tsx
// src/app/(frontend)/events/[slug]/page.tsx — EventPage
const design = designs[event.slug] ?? plainDesign
const { Page, Shell } = design

return (
  <Shell event={event}>
    <Page event={event} />
  </Shell>
)
```

## Client components

A file starting with `"use client"` ships JavaScript and may use state, effects,
refs, and browser APIs. `SeasonBooking`, `BookingFlow`, `SeatMap`,
`OrderConfirmation`, `Gallery`, `FooterGate`, and the design season wrappers are
client components.

The boundary matters: a server component cannot pass a function to a client
component. That is why `SeasonBooking` lives inside a client wrapper rather than
receiving a render function directly from the server page.

## Search params

`SeasonBooking` reads `?show=` with `useSearchParams()` and writes it with
`history.replaceState`. It does not use the router because the page should not
push a new history entry.

```tsx
// src/components/ticketing/SeasonBooking.tsx — SeasonBooking
url.searchParams.set('show', selectedShowId)
window.history.replaceState(null, '', `${url.pathname}${url.search}${url.hash}`)
```

## Route handlers

Payload's API and GraphQL routes are route handlers under
`src/app/(payload)/api/`. The planned `/ticket-api/[...path]` proxy would be the
route handler that forwards browser requests to Go at runtime. It does not exist
yet.

## Environment variables

`NEXT_PUBLIC_*` values are inlined at build time. The ticketing client chooses
mock or HTTP from `NEXT_PUBLIC_TICKET_API_MODE`, and `NEXT_PUBLIC_TICKET_API_BASE`
selects the HTTP base path. Changing either requires a rebuild.

## Hooks in use

- `useState` for selection, loading, notices, holds, and form fields.
- `useEffect` for initial loading, polling every 10 seconds before a hold, the
  hold countdown, and cleanup.
- `useRef` for the order token and stable handles.
- `useCallback` for refresh/selection functions passed to effects.
- `useId` for accessible form ids.
- `useMemo` for derived show state.
- `useSearchParams` for `?show=`.
- `useSyncExternalStore` in `OrderConfirmation` to read the session token
  without a hydration mismatch.

## Effects and cleanup

Effects must clear intervals and ignore late responses after unmount. The booking
flow stores the token in a ref, uses `clearInterval` for the countdown, and stops
polling once a hold exists.

## Types

`src/lib/ticketing/types.ts` is the contract for the Go API. `src/payload-types.ts`
is generated by Payload and must not be edited by hand. `tsconfig.json` enables
strict mode and unused-local checks.
